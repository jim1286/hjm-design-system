# 사용 지침 규격

검토일: 2026-10-17 · 선택적 형식 감사: `pnpm usage:check`(`scripts/check-usage-docs.mjs`)

2026-10-06 사용자 요청: 지침은 단계마다 같은 규격으로 나와야 한다. 그래야 에이전트가 어느 지침을 열어도
같은 자리에서 같은 정보(위치·크기·간격·순서·상태)를 찾고, 빠진 정보를 검사기가 잡는다. 자유 형식이던
첫 작성본은 같은 정보가 절마다 다른 이름·표 모양으로 흩어져 있었다. 형식은 탐색과 자동 색인 생성을 위한 작성 관례다. 제품 계약과 예제의 정확성은 유지하되,
절 순서·표 모양을 개발·npm 게시의 차단 조건으로 삼지 않는다. 규격 변경은 영향받는 생성기와 지침만 함께 갱신한다.

## 1. 공통

화면·구성은 [소유권](SELECTION.md#소유권)에 맞춰 HJM 공개 구현과 앱의 데이터/확장 입력을 구분한다.
기본 배치·상태·배지·상호작용을 제품이 재조립하도록 안내하지 않는다. 의도별 행동 위치는
[선택 기준](SELECTION.md#조립-규칙필수), 정확한 값·기본값은 contracts recipe와 공개 타입이 소유한다.
개별 지침은 해당 정본을 참조하고 다른 순서·숫자를 별도 규칙으로 만들지 않는다. 실행 예제만 있는 조합은
공개 구현 여부를 명시하고, 예제를 앱에 복사하는 대신 기존 HJM API를 보완한다.


- 파일 위치: `usage/<단계 폴더>/<영어 kebab-case>.md`. 컴포넌트는 공개 계약 이름의 kebab(`QRCode` → `qr-code`).
- 제목 한 줄 `# <이름>`. 컴포넌트는 공개 계약 이름(`# Button`), 나머지는 Storybook의 마지막 이름(`# 간격`).
- 제목 바로 아래 **머리말 목록**을 이 순서·이 키로 둔다. 값이 없으면 `없음`.

  ```markdown
  - 단계: 컴포넌트            # 토큰 | 컴포넌트 | 구성 | 화면
  - 상태: 배포                # Storybook 분류만 의미. API 안정성·npm 게시 상태가 아님
  - 지원: Web · Native        # Web · Native | Web | Native
  - 적용: 1.17.1              # 확인한 기본 API의 게시 버전. 최초 출시 버전이 아님; 조합 예제는 `구성 API 지침 참조`
  - 검토일: 2026-10-06
  - 근거: `../../button-label.md`(링크), `src/base-recipes.ts`   # 계약 문서·소스
  - 스토리북: `배포/컴포넌트/동작/버튼`   # 담당 제목 전부, 백틱. 구성·화면·토큰은 검사기가 이 줄로 담당을 판정
  ```

- 스토리북 담당 규칙: Storybook 제목은 모든 단계에서 `<배포|실험>/<단계>/<분류>/<항목>` 4마디다
  ([탐색 규격](../../../../docs/STORYBOOK_NAVIGATION.md#1-규격)). 모든 항목 제목은 어느 지침이 담당해야 한다.
  `컴포넌트/개요/...`(사용 안내·컴포넌트 찾기·구현·검증 현황·`<역할> 모아 보기`)는 탐색 문서라 대상이 아니다.
  - 토큰·구성·화면은 한 제목을 한 지침만 담당한다. 항목을 합치면 지침도 하나로 합친다.
  - 컴포넌트는 여러 계약을 한 항목에서 보일 수 있어 같은 제목을 함께 담당해도 된다. Web과 Native는 같은 개별 제목
    (`배포/컴포넌트/<역할>/<항목>`)을 쓴다. 2026-10-06 규격 전에는 Web 컴포넌트가 역할 묶음 안의 스토리 `name`이라
    `<묶음 제목>/<name>`으로 적었고, 이 키가 같은 이름의 개별 제목과 17개 겹쳤다. 같은 날 묶음을 `개요/<역할> 모아 보기`로
    옮기고 Web에도 개별 항목을 만들었다. 검사기의 옛 묶음 키 처리도 함께 지웠다.
  - 컴포넌트 지침은 그 API를 보여 주는 구성·화면 제목을 함께 적어 **참조**할 수 있다(담당은 그 단계 지침).
    화면급 API(ChatScreen·SearchScreen 등)가 예제가 있는데도 `없음`이던 것을 막는다.
  - `- 스토리북: 없음`은 어느 단계에도 그 API를 보여 주는 스토리가 없는 보조 API에만 쓴다.
  - 색인의 `분류` 열은 `스토리북:` 줄의 담당 제목 셋째 마디로 만든다(다른 단계 예제만 참조하는 컴포넌트는 `<단계>/<분류>`).
    머리말에 분류 키를 따로 두지 않는다. 2026-10-06 분류 어휘를 고정하면서 색인을 메뉴 순서로 묶었고, 키를 두면 제목과 두 벌이 된다.
- 색인과 필수 정보의 기준 절은 아래 이름·순서를 쓴다. 필요한 추가 설명 절은 허용한다. 필수(●)와 선택(○)은 정보의 유무를 구분한다.
  절 안에서는 `###`를 자유롭게 쓴다.
- 표는 단계 표에 적힌 **열 이름 그대로** 쓴다. 해당 없는 칸은 `—`.
- 숫자는 토큰 이름과 값을 함께 쓴다(`spacing.md` 16). 소스에서 확인한 것만 쓴다.
- **규칙과 관찰을 구분한다.** 스토리·소스가 다른 지침이나 토큰 규칙과 어긋나면(예: 제목을 `Text`로 그림, Native
  ScrollView에 여백을 직접 줌) 지침 본문은 규칙대로 쓰고 어긋남은 `## 함정`에 "현재 스토리는 …"으로 적는다.
  2026-10-06 블라인드 검증에서 화면 지침이 스토리 관찰값을 규칙처럼 옮겨 컴포넌트·토큰 지침과 충돌했다.
- 코드 예는 `strict` + `exactOptionalPropertyTypes`로 실제 공개 타입을 확인한다. `usage:check`는 문서 형식 검사이며 타입 검사 결과가 아니다.
- 같은 예제를 문서와 Storybook에 복사하지 않는다. 실행되는 TSX 원본을 참조할 수 있으며 플랫폼마다
  `<!-- usage-example: Web 상대/경로.tsx -->` 또는 `Native` 표시와 읽을 수 있는 링크를 함께 둔다.
  읽을 수 있는 링크는 npm에 포함되지 않는 `showcase/` 상대 경로 대신 확인한 commit SHA의 저장소 URL을 쓴다.
  설치 후 예제 링크가 끊긴 2026-10-17 점검에 따른 규칙이다. 예제를 바꿀 때 링크의 SHA도 함께 갱신하고,
  해당 SHA의 예제와 설치 버전의 공개 타입을 구분한다. 로컬 marker는 작성 시 원본 존재 확인용이다.
  검사기는 참조 파일의 존재만 확인한다. 변경한 원본은 해당 Showcase 타입 검사 또는 파일 지정 타입 검사로 확인한다.
  2026-10-13 설정 화면의 중복 코드 골격을 실제 Web/Native preview 참조로 교체했다. 제품은 예제를 읽고 공개 API를 사용하며 showcase를 import하지 않는다.
- 배치도는 ```text 블록 ASCII. 위→아래, 주 행동·보조 행동·고정 영역·스크롤 영역·안전 영역을 표시한다.
- 인라인 코드 예는 ```tsx 블록과 첫 줄 `// Web` 또는 `// Native`를 쓴다. 실행 원본 참조도 코드 예로 인정한다. 제품 문구는 i18n으로 공급한다.
- 규격 절 이름을 `###`로 내려 쓰지 않는다(표·행 검사를 피하게 된다). 다른 내용은 해당 규격 절 안의 `###`로 둔다.
- 링크: 같은 단계 `name.md`, 다른 단계 `../<폴더>/name.md`, 계약 문서 `../../<doc>.md`.
- 문체: 한국어 평서체(-다).

- 규칙과 근거를 나눈다. 본문(꼭 지킬 것·배치·상태 등)에는 규칙만 쓰고, 규칙이 생긴 계기(날짜·실측·사고·사용자 지시)는
  문서 끝 `## 근거` 절에 "규칙 이름: 날짜 계기" 한 줄로 남긴다. 근거를 지우지 않는다(포트폴리오 "결정에는 근거를 남긴다").
  호환 버전·측정 결과처럼 사용에 필요한 날짜는 본문에 둔다.

## 2. 단계별 절과 표

### 토큰 (`tokens/`)

| 절 | | 내용 · 고정 표 |
| --- | --- | --- |
| `## 언제 쓰나` | ● | 첫 문장이 색인 요약이 된다 |
| `## 값` | ● | `\| 토큰 \| 값 \| Web CSS 변수 \| Native 경로 \| 용도 \|` |
| `## 쓰는 법` | ● | Web·Native 코드 예 |
| `## 하지 말 것` | ● | 목록 |
| `## 플랫폼 차이` | ○ | `\| 항목 \| Web \| Native \|` |

### 컴포넌트 (`components/`)

| 절 | | 내용 · 고정 표 |
| --- | --- | --- |
| `## 언제 쓰나` | ● | 첫 문장이 색인 요약 |
| `## 쓰지 않을 때` | ● | `\| 상황 \| 대신 쓸 것 \|` |
| `## 공개 이름과 import` | ● | `\| 이름 \| 역할 \| Web \| Native \|` (역할: 기본·동반·확장·보조) |
| `## 최소 사용 예` | ● | Web·Native 코드 예(없는 쪽은 한 줄로 "없음") |
| `## 축과 기본값` | ○ | `\| prop \| 값 \| 기본값 \| 설명 \|`. 콜백은 값 칸에 시그니처(`(next: string) => void`), 상태 객체는 모양(`{ status, requestKey }`)까지 쓴다 |
| `## 배치` | ● | `\| 항목 \| 값 \| 근거 \|`, 행은 **크기 · 간격 · 순서·정렬 · 고정·스크롤 · 좁은 폭·큰 글자** 다섯 개 고정. 오버레이·고정 바·화면 골격은 배치도 추가 |
| `## 꼭 지킬 것` | ● | 목록 |
| `## 플랫폼 차이` | ○ | `\| 항목 \| Web \| Native \|` |
| `## 함정` | ○ | 목록, 검증된 것만 |

### 구성 (`compositions/`)

| 절 | | 내용 · 고정 표 |
| --- | --- | --- |
| `## 언제 쓰나` | ● | 첫 문장이 색인 요약 |
| `## 구성 요소` | ● | `\| 컴포넌트 \| 역할 \| 지침 \|` |
| `## 배치` | ● | 배치도 + `\| 영역 \| 컴포넌트 \| 위치 \| 크기·간격 \|`, 첫 행은 **바깥 틀**(스크롤 컨테이너·좌우 여백·안전 영역·키보드) |
| `## 흐름과 상태` | ● | 번호 목록(사용자 행동 순서) + `\| 상태 \| 모습 \| 포커스·알림 \|`, 행 **기본 · 진행 중 · 실패** 필수(해당 없으면 `—`) |
| `## 코드 골격` | ● | Web·Native 코드 예 |
| `## 플랫폼 차이` | ○ | `\| 항목 \| Web \| Native \|` |
| `## 함정` | ○ | 목록 |

### 화면 (`screens/`)

| 절 | | 내용 · 고정 표 |
| --- | --- | --- |
| `## 목적` | ● | 첫 문장이 색인 요약 |
| `## 영역 구조` | ● | 배치도(좁은 폭, 넓은 폭 Web이 다르면 하나 더) + `\| 영역 \| 컴포넌트 \| 위치 \| 크기·간격 \|`, 첫 행은 **바깥 틀** |

| `## 함정` | ○ | 목록 |

## 3. 원본과 확인 범위

선택은 [화면과 구성 선택](SELECTION.md)을 따른다. canonical API 안정성은 생성된 manifest에서 색인으로
읽고 별도 숫자나 stable 목록을 복제하지 않는다. 구성·화면의 `적용: 구성 API 지침 참조`는
본문의 API 링크를 따라 확인한다. `미게시(x.y.z 이후)`는 실제 미게시 추가분에만 쓴다.

`node scripts/check-usage-docs.mjs --files <지침 경로> ...`는 지정한 지침만 감사한다.
`--write`를 함께 주면 색인을 갱신한다. 전체 지침 감사는 명시적으로 선택할 때만 실행한다.
