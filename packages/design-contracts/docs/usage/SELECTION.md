# 화면과 구성 선택

검토일: 2026-10-17

이 선택 기준은 모든 화면·구성에 적용한다. **공통 구조는 HJM이 완성해서 제공하고, 앱은
데이터·문구·브랜드·권한·추가 기능을 연결한다.** 도입 계기는 [근거](#근거)에 있다.

## 작업 시작: 수정 위치 → 공개 API → 확인 범위

2026-10-18 사용자 요청: 에이전트가 여러 문서의 중복 규칙을 다시 해석하지 않고 필요한 구현으로
도달하도록 작업 진입점을 모았다. 아래는 기존 정본을 찾는 경로이며 새 승인·검사 절차가 아니다.

1. **수정 위치를 고른다.** 공통 배치·상태·상호작용 문제는 HJM, 데이터·문구·권한·서버 확정 문제는 제품이다.
   [소유권](#소유권)과 아래 [합성 경계 사례](#합성-경계-사례)로 구분한다. 원인이 불명확하면 해당 입력과 renderer를 추적한다.
2. **필요한 API만 찾는다.** [색인](README.md)에서 화면 → 구성 → 컴포넌트 → 토큰 순으로 찾고,
   선택한 API의 사용 지침과 실제 공개 타입·export를 읽는다. 모든 단계의 지침을 전부 읽는 순서가 아니다.
   기존 API가 부족할 때만 아래 선택 표로 확장 경로를 결정한다.
3. **실행할 소스를 확인한다.** 설치 패키지를 쓰는 경로는 그 버전의 지침·타입·export가 기준이다.
   로컬 소스 연결로 개발하는 경로는 실제 연결된 checkout을 기준으로 확인하고 설치 버전과 차이를 구분한다.
   로컬에서 보이는 미게시 prop을 production에서도 제공한다고 판단하지 않는다. 버전 상승·게시·제품 채택을 자동으로 붙이지 않는다.
4. **변경에 필요한 확인만 고른다.** HJM 수정은 checkout의 `CONTRIBUTING.md` → 「변경 유형별 작업 범위」,
   제품 수정은 제품 지침과 [소비 정책 §5](../consumer-policy.md#5-필수-검증과-evidence)를 따른다.
   문서만 바꾸면 설명·참조 연결, 동작을 바꾸면 관련 타입·동작, export·peer를 바꾸면 해당 의존 경계를 확인한다.
   전체 감사·빌드·게시를 일상 작업에 자동으로 추가하지 않는다.

브랜드 변경일 때만 [브랜드 경계](../brand-boundary.md), 새 공개 API 등록·승격일 때만
[등록·승격 기준](../stable-promotion.md)을 추가로 읽는다. HJM 게시 요청은 checkout의
`docs/RELEASE_GOVERNANCE.md`로 이어진다. npm에 없는 checkout 문서를 설치 패키지의 상대 링크로 찾지 않는다.
읽는 문서를 줄이는 것이 이미 적용되는 공통 규칙을 면제하지는 않는다.

## 선택 기준

선택 상태의 색상은 [기본 테마 선택 상태 기준](../theme-palette.md#선택-상태-색상-기준-2026-10-23)을 따른다.
지속되는 선택, 현재 조작 위치, 명시적 브랜드 강조를 구분하고 공통 recipe에서 연결한다.

이름을 모르면 [쉬운 말로 찾고 비교하기](FINDING.md)에서 일상 표현·유사 UI 차이·요청 예시로 시작한다.
Storybook의 기존 **컴포넌트 찾기**에서도 같은 쉬운 말로 검색해 실행 예제를 연다.

| 선택 | 조건 | 구현 경로 |
| --- | --- | --- |
| 그대로 사용 | 제공하는 화면·구성이 제품의 목적에 맞는다 | HJM 공개 API에 데이터·문구·콜백 연결 |
| 공개 슬롯으로 확장 | 기본 흐름은 같고 제품 콘텐츠·추가 행동이 필요하다 | 정해진 슬롯에 콘텐츠를 공급하고 배치·상태 엔진은 HJM 유지 |
| 공통 API 보완 | 가상화·새 영역·동작을 기존 API로 표현할 수 없다 | HJM의 기존 구현을 확장하거나 공통 하위 구성을 공개한 뒤 앱에서 사용 |
| 제품 고유 기능 | 지도·편지·도구 실행 등 제품만의 도메인 경험이다 | HJM의 화면·구성 안 콘텐츠 슬롯에 연결. 제품 기능을 이유로 공통 헤더·입력·상태·배지를 복제하지 않음 |

## 소유권

| HJM이 제공하는 것 | 앱이 공급하는 것 |
| --- | --- |
| 영역 순서, 간격·정렬·폭, 헤더·본문·footer, 반응형 배치 | 제목·문구·브랜드 설정·실제 콘텐츠 |
| 목록 항목, 아바타·시각·배지·반응·메뉴의 기본 자리 | 작성자·시각·배지 의미/값·반응 종류·메뉴 항목 |
| 초기 로딩·빈 상태·오류의 영역 중앙 표시, 비차단 안내 자리 | 조회 상태·오류 문구·재시도 콜백 |
| 작성창·답장 대상·첨부·전송 상태, 확장 영역 배치 | 초안·수신 결과·사진 권한/업로드·제품 도구 카드 |
| 펼침·전환·포커스·제스처·접근성 표현 | 권한 판정·라우팅·서버 요청·저장·도메인 규칙 |

슬롯은 콘텐츠와 추가 기능의 연결점이다. header·footer·children이 ReactNode라는 이유로
제품에서 동일한 기본 구조를 다시 만드는 허용 경로로 해석하지 않는다. 배지는 의미·값을 앱이
결정하고 위치·간격·넘침 표현은 해당 HJM 구성과 Badge 계약을 따른다.

### 합성 경계 사례

| 필요한 변경 | 구현 위치와 연결 | 경계를 넘는 구현 |
| --- | --- | --- |
| 검색 결과에 제품의 지도 추가 | 제품 지도 기능을 선택한 화면 API의 콘텐츠 슬롯에 연결. 검색 입력·필터·상태 배치는 HJM 유지 | 지도 화면이라는 이유로 검색창·도구·빈 상태 틀까지 제품에서 재구현 |
| 탐색과 도구를 헤더 한 행에 배치 | `ScreenLayout.header`에 HJM `TopBar`를 연결하고 공개 `leading`·`actions` 사용 | 앱의 `View`/`div`로 헤더 정렬·높이·행동 위치를 다시 정의 |
| 댓글 목록을 가상화 | 제품은 가상화 host·데이터를 연결하고 행은 `CommentThreadRow` 등 공개 공통 표시 사용 | 가상화를 이유로 아바타·배지·메뉴·답장 배치를 제품 행에 복제 |
| 검색 빈 상태가 위쪽에 붙음 | 제품이 상태와 host 높이를 올바르게 전달하는지 확인. 입력이 맞으면 HJM의 해당 상태 영역 배치를 수정 | 제품별 spacer·margin으로 중앙처럼 보이게 보정 |
| 저장 실패 때 입력이 사라짐 | 제품의 draft·요청 확정 처리와 HJM 콜백을 추적해 값을 지우는 소유 지점을 수정 | UI에 이전 값을 따로 복제해 실제 상태 오류를 감춤 |

기존 공통 API의 합성은 허용한다. 합성할 때 공통 영역의 위치·상태 엔진까지 새로 정의해야 한다면
HJM의 기존 API를 확장하거나 하위 구성을 공개한다. 도메인 로직은 그 확장에 옮기지 않는다.
표의 API도 실행할 버전의 공개 타입·export에서 지원을 확인한다.

## 조립 규칙(필수)

예제·제품 화면 모두 아래 표의 컴포넌트를 쓴다. 버튼·글자로 대체 조립하지 않는다.

| 의도 | 쓸 것 | 쓰지 않을 것 |
| --- | --- | --- |
| 하나 고르기(주제·정렬·탭) | `Chip`(`selectionMode="single"`), `SegmentedControl`, `RadioGroup` | `selected`를 준 `Button` 나열, `ToggleGroup`(단일 모드가 없는 다중 토글 계약) |
| 여러 개 고르기 | `Chip`(`selectionMode="multiple"`), `CheckboxGroup`, 짧은 서식·필터 토글 묶음은 `ToggleGroup` | 버튼 토글 |
| 켜고 끄기 설정 | `Switch`(제목·설명 포함), 설정 목록은 `ListRow` + `Switch` | "○○ 켜짐/꺼짐" 글자 버튼 |
| 주 행동 | 화면 지침의 "버튼과 행동 위치"대로 하나의 primary, 하단 고정이면 `BottomCTA`/`footer` | 같은 표면에 경쟁하는 primary 여럿, 폭이 제각각인 버튼 줄 |
| 보조 행동 | 주 행동 아래 같은 폭 secondary, 또는 헤더 `actions` | 본문 중간에 흩어진 버튼, 나가기를 보조 행동으로 두기 |
| 상태·결과 안내 | `Notice`, `Badge`, `ListRow` 설명 | 가운데 정렬 일반 글자 |
| 예제 전용 도구(실패 예약 등) | "미리보기 도구" 캡션 아래 `Button size="small" tone="ghost"`로 분리 | 제품 행동과 같은 모양·폭 |
| 헤더 제목·추가 기능 | 하단 탭·상단 탐색과 중복되는 최상위 화면명은 `titleVisibility="hidden"`. 식별에 필요한 대상·하위 작업명은 유지하며 본문과 중복되면 생략. 보이는 제목은 기본 가운데(`ScreenLayout`·`TopBar`, 왼쪽 정렬은 선택), 도구는 `actions` 아이콘 1~2개(넘치면 Menu) | 모든 제목 일괄 숨김, 위치 이름의 반복, 헤더의 글자 도구 버튼 |
| 상단 탐색과 도구 한 행 | `ScreenLayout.header`에 HJM `TopBar`, `leading`에 HJM `Tabs`/`SegmentedControl` 탐색, `actions`에 아이콘 도구. 탐색이 화면명을 대신한다. 본문 추가 필터는 `notice`/본문 유지 상단 일반 도구는 `size="small" hitSlop={0}`·간격 `spacing.xxs` 4를 사용한다([TopBar](components/top-bar.md#상단-도구의-공통-크기), 2026-10-21 사용자 승인). | 제목 행 + 같은 화면을 설명하는 탐색 행, 앱에서 직접 만든 헤더 레이아웃 |
| 상단 검색·장소 입력 | `SearchScreen`의 `queryLabelVisibility="hidden"`(기본). `queryLabel`은 placeholder와 접근성 이름, 뒤로가기·입력·오른쪽 도구는 공통 행에서 세로 중앙 | 입력 위 안내 label로 행 높이를 늘리기, 아이콘을 label 포함 높이에 맞추기, 일반 폼 label까지 숨기기 |
| 도구성 행동(새로고침·재시도·다시보기·재생/일시정지·추가·편집·삭제·공유·검색·필터·더보기) | `IconButton` + 아이콘, 글자는 `label`(보조기술 이름). HJM 화면은 아이콘 슬롯(`ScreenFlowAction.icon` 등) | 헤더·행·도구 막대의 글자 버튼 |
| 화면 나가기(뒤로·닫기·설정 나가기) | `ScreenLayout`(과 이를 쓰는 화면)·`AuthScreenLayout`의 `exit` — 헤더 시작 쪽 아이콘 버튼, 글자 없음. 단계형 작성의 앞 단계는 `EditorScreen` `stepBack`(1.31.0) | 본문·하단의 "나가기" 글자 버튼, 화면마다 다른 화살표, 로그인·작성 화면 위에 따로 얹은 `TopBar` |
| 버튼 묶음 간격 | 일반 행동 묶음은 가로·세로 `gap="xs"`(8) — `actionGroupRecipe`. 상단 도구 줄만 `gap="xxs"`(4), `size="small" hitSlop={0}`(2026-10-21 사용자 승인) | 세로 버튼 사이 12 이상 |
| 나란한 컴포넌트 높이 | 항상 같은 높이로 위·아래 경계를 맞춘다. 버튼·필터·탭·선택 카드·입력/아이콘 도구 모두 포함. 여러 줄이면 같은 행의 가장 높은 콘텐츠에 맞추며 줄바꿈 그리드는 행별 적용. 세로의 동일 행동 묶음도 같은 크기 규격. 공통 renderer/그리드가 소유(2026-10-20 다에리 선택 카드 높이 불일치 사용자 지적) | 문구·아이콘·선택/강조 상태마다 다른 높이, 내용 자르기·글자 축소·넘치는 고정 높이로 맞추기 |
| 상단 영역과 본문 연결 | 상태바·노치/Dynamic Island safe area → 헤더 → 본문 첫 배경을 연속된 바탕으로 연결한다. 안내·캐릭터/말풍선·브랜드 영역의 배경/표면 전환·좌우 경계·여백도 연결한다. 고정/접힘 상단은 실제 높이를 공통 화면/스크롤 host에 반영해 본문을 가리지 않는다(2026-10-20 다에리 사용자 지적) | 하늘색 상태바/장면 사이의 짙은 헤더 띠, 상태바만 별도 덧칠, 불필요한 빈 띠·굵은 선·중복 테두리/그림자, 상단 아래 본문 가림, 제품별 좌표/보정 여백 덧대기 |
| 레이아웃 바깥 여백·본문 폭 | `ScreenLayout`·부모 콘텐츠 영역의 좌우 바깥 여백은 항상 같은 값, 상하 바깥 여백도 같은 기준. 같은 영역의 카드·입력·목록·버튼 묶음은 동일 폭·경계. 카드 내부 내용·padding은 해당 recipe 유지(2026-10-19 사용자 명확화) | 서로 다른 본문 폭, 한쪽 margin·고정 폭 왼쪽 몰림으로 생긴 바깥 여백 불일치 |
| 앱·모바일 웹뷰 글자 | 본문·라벨을 기본으로, 제목은 필요한 최소 단계. 굵기·간격으로 위계를 만들고 기존 24 상한을 기본값으로 사용하지 않는다(2026-10-19 사용자 지시) | 큰 구획 제목·히어로 문구·과도하게 큰 숫자 |
| 페이지 진입 시 입력 포커스 | `ScreenLayout`·`AuthScreenLayout`의 기본 `first-input`, 주 입력 지정은 `initialFocusTarget`. 상단·본문 입력만 대상이고 `ScreenLayout.footer`의 하단 작성창은 제외한다(checkout 변경·미게시). 하단 시트는 자동 입력 포커스 없음([진입 포커스](components/screen-layout.md#진입-포커스), 1.33.0 정책 변경) | 앱별 `autoFocus`·지연 `ref.focus()`·단계 전환·시트 열기 뒤 자동 포커스 |

리뷰 기준: 위 "쓰지 않을 것" 패턴이 보이면 예제 조립 문제인지 컴포넌트 recipe 문제인지 먼저 가리고, 원인 쪽(예제 또는 HJM 컴포넌트)을 고친다.

2026-10-20 스크롤 상단 연결: 콘텐츠 위의 투명한 상단 바를 우선하고 장면은 그 뒤로 이어진다. 필요한 컨트롤 면은 유지하며, 가독성이 필요할 때만 반투명/부드러운 scroll-edge 효과를 사용한다. 고정 색 띠로 덮지 않는다. 상태바·safe area도 스크롤 배경 전환을 함께 따르고, 공통 host가 헤더의 실제 높이를 측정해 첫 콘텐츠를 보호한다. 맨 위/중간/본문/복귀 상태를 확인한다. 다에리 스크롤 단절 지적 및 [Apple](https://developer.apple.com/videos/play/wwdc2025/356/)·[React Navigation](https://reactnavigation.org/docs/elements/) 공식 사례에 근거한다. Native에서는 로컬 `ScreenLayout.headerPosition="overlay"`와 `TopBar.surface="transparent"`로 연결한다(미게시).

## 구현과 확인

- 화면 → 구성 → 컴포넌트 → 토큰 순으로 찾고 기존 공개 API와 양 renderer를 먼저 확인한다.
- 기존 API가 부족하면 HJM 내부 구현을 분리·확장한다. 같은 구성에 대한 앱별 대체 엔진을 만들지 않는다.
  가상화 host는 제품이 연결할 수 있지만 댓글 행은 `CommentThreadRow`처럼 공통 표시를 재사용한다.
- 웹/RN은 플랫폼 adapter가 다르더라도 영역 순서·기본값·상태 의미를 공유한다. Native safe area·키보드와
  Web host 높이는 외부 환경 입력이며 같은 inset·스크롤을 두 번 적용하지 않는다.
- 서버 실패·초안·권한은 제품 상태가 정본이다. HJM은 성공을 추정하거나 초안을 임의로 지우지 않는다.
- Showcase는 HJM 공개 구현에 fixture를 연결한다. fixture의 예시 데이터·지연·브랜드·제품 메뉴를
  운영 기능으로 복사하지 않는다. 공개되지 않은 예제 조합은 먼저 HJM API로 옮겨야 하며,
  문서가 있다는 이유로 재사용 구현이 완성됐다고 보고하지 않는다.
- 기존 소비 화면은 기능을 보존하며 이관한다. 설치 버전의 지원 여부를 확인하고 HJM 변경·제품 채택·
  화면 확인·게시를 구분한다. 새로운 전수 검사·승인 게이트를 추가하지 않는다.

## 상태와 버전 읽기

| 정보 | 원본 | 해석 |

| 제공 기준 | 컴포넌트 지침의 적용 버전과 설치 패키지 exports/타입 | 확인한 기본 API의 게시 버전이며 최초 출시 버전이나 후속 prop 전체의 제공 보증은 아님 |

## 더보기 메뉴의 표현 선택 — 개발 소스, 미게시

2026-10-20 메뉴 행의 경계가 흐린 유틸버스 실화면과 세 가지 참고 시안에 대한 사용자 결정에 따른다.
[Menu 선택 지침](components/menu.md#세-가지-표시-방식--개발-소스-미게시)의 `presentation`으로
화면 전체 행동은 `grouped`, 댓글·목록 항목처럼 대상에 붙는 행동은 `anchored`, 모바일 하단 행동 목록은 `bottom`을 고른다.
공통 화면이 기본값을 소유하며 댓글 `commentMenu`는 `anchored`가 기본이다. 제품은 허용 항목·문구·아이콘·행동을 넣고
모달 틀·구분선·위치·닫힘 순서를 복제하지 않는다. 항목 수에 따라 표현을 자동 변경하지 않는다.
입력 작업은 Dialog/Sheet, 짧은 확인은 AlertDialog이며 메뉴와 역할을 섞지 않는다.

2026-10-20 전사 메뉴 적용: 화면 전체 행동은 그룹형, 콘텐츠/작성자/댓글/메모의 행동 및 정렬/분할 버튼의
모드 선택은 앵커형을 명시한다. 모바일 작품 관리 묶음은 하단형, 같은 웹 작업은 그룹형으로 제공한다.
HJM 공통 구성이 선택을 소유하고 제품 adapter는 `presentation`을 전달한다. 반응·원문 미리보기를 포함한
채팅 hold 구성과 입력/미디어/언어 선택 시트를 일반 Menu로 바꾸지 않는다. 자세한 사례와 경계는
[Menu 전사 개발 선택](components/menu.md#전사-개발-적용-선택--2026-10-20)을 따른다.

2026-10-23 사용자 지시: 익숙한 아이콘 하나로 의미를 전달할 수 있는 보조 행동은 본문·오류 안내에서도 `IconButton`을 사용한다. 접근성 `label`과 Web 설명(title/Tooltip), pending·disabled·포커스 복구를 보존한다. 재전송은 refresh, 이전 상태로 돌아가기는 되돌리기 아이콘으로 구분한다. 메뉴 행의 이름과 삭제 확인·결제·동의 같은 최종 의사 확인 문구는 유지한다.
