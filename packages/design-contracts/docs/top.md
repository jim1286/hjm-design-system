# Top contract

**문제.** 화면 본문의 첫 블록 — 사용자가 "이 화면이 무엇을 묻는지" 읽는 제목과 보조
문장. 토스 TDS가 "Top과 ListRow로 화면 대부분을 만든다"고 말하는 그 Top이다.

**TopBar와 다른 자리.** 이름이 비슷해서 합치고 싶어지지만 다른 문제다.

| | TopBar | Top |
| --- | --- | --- |
| 정체 | 화면에 고정된 크롬 | 스크롤과 함께 움직이는 본문 |
| 내용 | 뒤로가기·화면 이름·액션 | 제목·보조 문장·보조 행동 |
| 관심사 | safe area, 고정, 축약 | 읽기, 줄바꿈, heading 구조 |
| 접근성 | 내비게이션 landmark | 실제 `h1`/`h2` |

**Section과도 다르다.** Section은 본문 *중간*의 묶음 제목이라 heading level이 주변
구조에 종속된다. Top은 화면당 하나뿐인 첫 제목이라 기본이 `1`이다. 합치면 "이 Section이
이 화면의 h1인가"를 매번 물어야 하고, 그 질문은 컴포넌트가 아니라 화면이 답해야 한다.

**크기는 둘뿐이다.** `large`(화면의 첫 제목)와 `medium`(시트·모달 안의 첫 제목).
세 번째가 필요해지는 자리는 이미 `Section`이다 — 크기를 늘리는 대신 다른 컴포넌트를
쓰라는 신호로 둔다. 두 크기 모두 기존 타입 스케일(`heading.level2`, `typography.titleLarge`)을
그대로 쓰고 새 숫자를 만들지 않는다.

**잘리지 않는다.** `description`은 줄바꿈하며 말줄임하지 않는다. 큰 글자 설정에서 화면이
묻는 내용이 사라지면 안 되기 때문이다. `trailing` 보조 행동은 제목 줄을 공유하다가
공간이 부족하면 아래로 내려간다.

**eyebrow 규칙.** 제목이 어떤 형태로든 담고 있지 않은 정보를 eyebrow에 넣지 않는다.
카테고리·단계 표시처럼 제목을 한정하는 짧은 말만 쓴다.

**상태가 없다.** controlled 축이 없고 키보드도 dismiss도 없다 — 화면이 제목을 바꾸면
다른 문자열을 넘기면 된다.
