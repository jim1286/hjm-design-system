# Sidebar contract

**문제.** 데스크톱 웹의 세로 내비게이션 — 관리자 화면, 문서, 작업 도구처럼 넓은 화면의
왼쪽. 커버리지 감사에서 "데스크톱 앱 셸이 없다"로 꼽힌 자리다.

**BottomNavigation과 합치지 않는다.** 두 축이 다르다.

| | BottomNavigation | Sidebar |
| --- | --- | --- |
| 항목 수 | 3~5개 최상위 목적지 | 그룹이 있는 긴 목록 |
| 그룹 | 없음 | 있음(제목 있는 묶음) |
| 밀도 | 고정 | 접힘 |
| 표면 | 모바일 하단 고정 | 데스크톱 좌측 |

`orientation` 축으로 합치면 "그룹이 있는 하단 탭바"라는 존재하지 않는 조합이 타입에 생긴다.

**Layout과도 다르다.** Layout은 **자리**(폭·순서·반응형)를 갖고 내용을 모른다. 이 계약은
그 자리에 들어가는 내비게이션 자체다.

**접힘은 밀도이지 내용이 아니다.** 접혀도 항목은 전부 남고 라벨만 숨는다. 접을 때 항목을
빼면 "접었더니 메뉴가 사라졌다"가 되고 그건 다른 컴포넌트다. 라벨이 숨으면 아이콘만으로는
이름을 알 수 없으므로 renderer가 `aria-label`로 접근성 이름을 유지하고, 배지는 접힌
상태에서도 남는다 — 배지가 곧 그 항목을 봐야 할 이유이기 때문이다.

**현재 위치는 색이 아니라 `aria-current="page"`가 말한다.**

**tab stop.** 각 항목이 링크이고 문서 순서대로 놓인다. 화살표 grid 탐색을 도입하지 않는다.

**Web 전용.** 폰은 BottomNavigation을 쓰고, 네이티브 태블릿의 split view는 navigator의
문제다.
