# Sidebar contract

**문제.** 데스크톱 웹의 세로 내비게이션 — 관리자 화면, 문서, 작업 도구처럼 넓은 화면의
왼쪽. 커버리지 감사에서 "데스크톱 앱 셸이 없다"로 꼽힌 자리다.

**BottomNavigation과 합치지 않는다.** 두 축이 다르다.

| | BottomNavigation | Sidebar |
| --- | --- | --- |
| 항목 수 | 3~5개 최상위 목적지 | 그룹이 있는 긴 목록 |
| 그룹 | 없음 | 있음(제목 있는 묶음) |
| 밀도 | 고정 | 접힘 |
| 표면 | 모바일 하단 고정 | 데스크톱 좌측 |

`orientation` 축으로 합치면 "그룹이 있는 하단 탭바"라는 존재하지 않는 조합이 타입에 생긴다.

**Layout과도 다르다.** Layout은 **자리**(폭·순서·반응형)를 갖고 내용을 모른다. 이 계약은
그 자리에 들어가는 내비게이션 자체다.

**접힘은 밀도이지 내용이 아니다.** 접혀도 항목은 전부 남고 라벨만 숨는다. 접을 때 항목을
빼면 "접었더니 메뉴가 사라졌다"가 되고 그건 다른 컴포넌트다. 라벨이 숨으면 아이콘만으로는
이름을 알 수 없으므로 renderer가 `aria-label`로 접근성 이름을 유지하고, 배지는 접힌
상태에서도 남는다 — 배지가 곧 그 항목을 봐야 할 이유이기 때문이다.

**현재 위치는 색이 아니라 `aria-current="page"`가 말한다.**

**tab stop.** 각 항목이 링크이고 문서 순서대로 놓인다. 화살표 grid 탐색을 도입하지 않는다.
접기 버튼이 있으면 링크 앞에 일반 버튼 tab stop으로 놓인다. 긴 항목명과 그룹 제목은 고정 폭 레일을
넓히거나 내용을 자르지 않고 줄바꿈한다. 특히 공백 없는 로컬라이즈 문자열도 그룹의 의미가 보이도록
같은 규칙을 적용한다.

**Web 전용.** 폰은 BottomNavigation을 쓰고, 네이티브 태블릿의 split view는 navigator의
문제다.

## 선택형 Web 표현 — 2026-10-01

`appearance`는 standard(기본), bounce, hook, proximity를 지원한다. bounce는 새로 선택한 항목의 아이콘에 한 번만 적용하고, hook은 선택 항목의 시작 쪽 곡선 경계를 강조한다. proximity는 마우스/펜의 세로 거리에 따라 아이콘만 최대 18% 확대한다. 링크 경계와 키보드 순서는 변하지 않는다. 터치는 근접 효과를 만들지 않는다. HJM provider의 모션 줄이기에서 동적 표현을 끄며, provider 없이도 기본 정적 탐색은 가능하다.

독립적으로 구현한 제한된 표현이다. 원본 사이트의 모션 엔진을 복제하지 않았다. Web 전용이라는 기존 지원 범위를 유지하며 Native에서 새 사이드바를 만들지 않는다. Storybook `컴포넌트/탐색/Sidebar Motion`의 Default/Dark/LargeText에서 네 가지 표현과 접기를 비교한다. 기존 앱 셸 예제는 컴포넌트/탐색/Sidebar에 남는다.

## 프로필 모서리·제목 소비

2026-10-07 소비 감사에서 Web 항목의 숫자 recipe 모서리가 프로필을 우회했다. 기존 `radius.md` 역할을 가까운 Provider의 CSS 변수로 읽고 변수 없는 독립 사용은 recipe 12를 유지한다. 레일 폭·링크·현재 위치·접기·초점과 Web 전용 범위는 바꾸지 않는다.

프로필 연결은 1.15.0 이후 미게시 변경이며, 기본 배포 계약과 실제 Native 기기 검증은 구분한다.
