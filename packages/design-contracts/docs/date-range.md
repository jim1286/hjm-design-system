# DateRange contract

**문제.** 날짜 **구간** 선택 — 통계 기간, 예약, 검색 필터.

**Calendar에 `mode` 축을 넣지 않은 이유.** 단일 선택의 값은 `string | null`이고 구간의
값은 `{ start, end }`다. 한 컴포넌트가 두 값 모양을 가지면 모든 소비자가 매번 좁히기를
해야 하고, "range 모드인데 `selectedDate`를 준" 조합이 타입에 남는다. 격자는 그대로
재사용하고 **구간 판정만** 이 모듈이 갖는다.

**다음 클릭이 무엇을 하는가.**

| 현재 | 클릭 | 결과 |
| --- | --- | --- |
| 비어 있음 | 아무 날 | 시작 |
| 고르는 중(시작만) | 시작 이후 | 끝 확정 |
| 고르는 중(시작만) | 시작 이전 | 두 값을 **바꿔 담는다** |
| 완성됨 | 아무 날 | 새로 시작 |

완성된 구간을 다시 눌렀을 때 가까운 끝을 옮기는 동작은 넣지 않았다 — "어느 쪽 끝인가"를
추측해야 하고, 추측이 틀리면 사용자가 왜 그렇게 됐는지 알 수 없다. 다시 시작하는 쪽이
예측 가능하다. 시작보다 앞선 날짜를 거절하지 않고 바꿔 담는 것도 같은 이유다.

**"고르는 중"은 별도 플래그가 아니다.** `start`가 있고 `end`가 없는 상태가 그것이다.
플래그를 두면 플래그와 값이 어긋난 상태가 표현 가능해진다.

**미리보기는 같은 함수를 쓴다.** `resolveDateRangeCellState(value, date, hoveredDate)`가
확정된 구간과 hover 미리보기를 함께 처리한다 — renderer가 두 벌의 칠하기 규칙을 만들지
않게 한다.

**Native.** renderer는 아직 없다(catalog `planned`). 구간 선택은 제스처·스크롤과 함께
검증해야 해서 Web 먼저 낸다.
