# QA 리포트 — 버튼 결과 피드백과 높이 전환

## 판정·대상

부분 확인. 2026-10-07, Codex, main 7c47de5 위 Showcase·사용 지침 수정.
버튼 실패·편집 후 저장 의미와 패널 전환 시 입력 보존을 실제 조작했다.
전수 조사·승격·npm 게시·Utilverse 채택은 아직 완료하지 않았다.

## 환경

Web IAB localhost6006: 버튼 기본/light 및 dark/textScale2, 패널 dark/textScale2.
좁은 화면은 각각 최종 캡처에서390×844를 확인했다. 초기 버튼 실패 캡처는1280×720이다.
Native 기존 iPhone17Pro/iOS26.5, Expo Go57.0.9, Metro8084, light/기본 글자.
Native 확인은 idb·simctl 대체 도구다. 직접 Device Hub 창·실물 Release 검증은 아니다.

## 버튼: 재현·수정·결과

- 빈 제목은 저장 비활성. Web에 `실패 뒤 수정할 제목` 입력→다음 저장 실패 선택→저장.
  pending에서 저장 비활성, 실패 후 같은 입력·버튼 초점이 남았다.
- 실패 뒤 `수정한 제목`으로 바꿔 다시 저장하면 결과는 수정한 제목이었다. 기존 사용 지침의
  “재시도도 같은 입력”은 실제 코드와 달랐다. 현재 초안 저장과 원요청 재시도를 구분해 정정했다.
- 양 예제에 실제 서버 요청이 없다는 안내를 항상 표시한다. 저장 중 실패 체험 설정을 잠그고,
  버튼 children을 `기록 저장 중`으로 바꾼다. 초기 변경에 넣었던 미지원 loadingLabel prop은
  typecheck에서 거부되어 제거했고, 실제 Button API로 다시 검사했다.
- 수정 후 Web AX는 저장 중 이름·버튼 비활성·실패 설정 비활성을 확인했다. 완료 뒤 다시
  활성화되고 저장한 제목42가 표시됐다. 390px dark/textScale2 전체 화면에서 입력·결과·안내가
  보이고 버튼 잘림은 없었다. 초기 실패 검증과 최종 성공 검증은 별도 실행이다.
- Native 제목42→실패→421로 편집→다시 저장→저장한 제목421. 키보드가 열린 상태에서
  입력과 행동이 보이고 실패 문구·서버 요청 없음 안내를 캡처로 확인했다. 실제 서버 저장은 아니다.

## 패널: 재현·결과

- Web390px dark/textScale2에서 메모 `전환 후에도 보존` 입력 후 상세 선택.
- 상세 내용이 모두 나타나고 입력은 아래로 이동했다(화면 기준 top649px).
- 상세에서 ArrowUp→요약, ArrowDown→상세, ArrowUp→요약을 연속 실행했다.
  최종 요약만 남고 제목 노드1개, 입력 값 유지, 가로 overflow 없음.
  마지막 관측의 입력 top393.95px는 전환 중 값일 수 있으므로 최종 정착 높이로 단정하지 않는다.
- 상세 화면 캡처에서 내용·입력 겹침과 잘림은 없었다. 입력은 ContentTransition 바깥이라
  내용 교체에서 제거되지 않는다. 인위적 상태 복사나 exit 콘텐츠 중복을 추가하지 않았다.
