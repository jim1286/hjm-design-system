# 새 데이터 목록 전환 검증

- 날짜: 2026-10-07
- 대상: HJM ContentTransition / Web·Native `추가해도 유지되는 목록` 실험
- 상태: 구현·일부 UI 검증, 승격·게시·Utilverse 채택 전

## 조사와 결정

[Magic UI 문서](https://magicui.design/docs/components/animated-list)와
[공식 소스](https://github.com/magicuidesign/magicui/blob/main/apps/www/registry/magicui/animated-list.tsx)를
확인했다. 소개용 정적 데이터를 일정 간격으로 노출하며 순서를 뒤집는다. 원본 IAB light
1280×720에서 처음 한 카드 이후 여러 알림 카드가 나타나는 것을 관찰했다. 원본의 다크·접근성·반응형
전체는 아직 확인하지 않았다. 소스의 timer, index, AnimatePresence 엔진을 복사하지 않았다.

기존 ContentTransition은 초기 mount에 모션이 없어서 stable key의 새 행을 등장시킬 수 없었다.
Web·Native에 기본 false인 enterOnMount를 추가했다. 기존 stateKey 변경 계약과 optional peer 경계는
유지한다. 별도 AnimatedList 엔진·배포 이름은 만들지 않는다. 실제 데이터는 즉시 반영하며 삭제는
즉시 unmount한다. 재정렬은 데이터 순서만 바꾸고 sibling 이동 애니메이션은 아직 제공하지 않는다.

## 재현과 수정

1. 초기 기록 1의 메모를 수정한다.
2. 3개 함께 추가 후 기록 1의 값·id 유지와 전체 4개 데이터 반영을 확인한다.
3. 순서를 뒤집고 기존 기록이 같은 값을 가진 채 이동하는지 확인한다.
4. 첫 기록 삭제 후 그 입력 대상이 제거되는지 확인한다.
5. 움직임을 멈춘 상태에서 추가해도 데이터가 즉시 표시되는지 확인한다.
6. 모두 삭제한 뒤 다시 추가할 수 있는지 확인한다.

Web 마지막 항목 삭제 때 삭제 버튼 자체가 disabled가 되며 초점이 body로 떨어지는 것을 발견했다.
빈 상태에서는 먼저 기록 추가 버튼에 초점을 옮기도록 수정했다. 공유 예제에 React hook을 두면
Native TypeScript가 shared 폴더의 React 타입을 해석하지 못해 실패했다. React 상태는 각 renderer
예제에 두고 공통 파일은 순수 데이터 처리만 맡도록 수정했다. root에 React 의존성을 더하지 않았다.

## 자동 검증

- 집중 Web 12개 통과: 새 항목 즉시 DOM 반영·stable input 유지·재정렬 중 초점·삭제 대상 제거·모션 감소와 기존 전환 회귀.
- 집중 Native 9개 통과: 신규 mount 1회 전환·pause/재개 시 재생 없음·reduced motion·기존 background 취소 회귀.
- 전체 pnpm ci:check는 contracts 960, Web node 278/browser 1,092, Native 1,190 및
  renderer graph/workspace/evidence/docs/governance/API map 검사까지 통과한 뒤 신규 사용 지침의
  필수 배치·상태·Native 코드 절 누락으로 실패했다. 해당 문서 수정 후 usage:sync와 storybook:check를 다시 실행했다.
- Web content-transition graph: 4 modules / raw 24.2 kB / gzip 6.7 kB.
- Native content-transition graph: 5 modules / raw 27.5 kB / gzip 7.4 kB. 추가 peer 없음.

## 실제 UI와 한계

- Web IAB: 입력 수정·3개 추가·재정렬·삭제 후 기존 값과 input id 유지. 움직임 정지 중에도 추가 반영.
- Web 다크 표면과 390×844 큰 글자 배치를 확인했다. 최초 화면 크기 제어가 다른 탭에 적용되어 1280px였던 관찰은 390px 증거에서 제외했다. 새 대상 탭의 innerWidth=390, 가로 overflow=false와 화면을 확인했다. 마지막 삭제 후 기록 추가 버튼으로 초점 복귀·빈 상태에서 재추가를 최종 소스로 확인했다.
- iOS 기존 iPhone 17 Pro / iOS 26.5, Expo Go 57.0.9, localhost:8084에서
  `작성 중인 메모1` 입력 후 3개 추가·역순 변경 시 같은 값 유지 확인. idb 조작이며 직접 Device Hub 창,
  실물 기기 또는 Release 성능 검증이 아니다. 초기 idb text 입력은 키보드 준비 전에 들어가 무효였으므로
  숫자 키를 직접 눌러 변경한 흐름만 증거로 삼았다.

전체 상태 모아보기, 두 제품 팔레트, RTL·모션 감소 실제 화면 조합, Native 다크·큰 글자·삭제 끝 상태,
대량 데이터 성능·프레임·스크린리더를 포함한 승격 검증은 남았다. 기본 기능 검증을 전수 검증으로 세지 않는다.


## 최종 검사와 증거 정리

문서 수정 후 usage:check·storybook:check 통과(409 files / 900 Web ids).
수정된 공유 데이터 구조로 Showcase Native typecheck/18 tests, Web typecheck/43 tests/token 검사,
production Storybook build와 static verify(103 canonical components / 13 navigation pages)가
각각 exit 0으로 끝났다. 최종 iOS 소스로 메모1 입력 → 3개 추가 → 역순 → 같은 값 유지를 다시
확인하고 simctl 캡처를 관찰했다. Storybook 개발 도구가 화면 오른쪽·하단에 겹치므로 해당 UI를
제품 완성 화면으로 간주하지 않는다. 프레임 시간·실물 기기 성능 측정은 하지 않았다.

실험은 13개로 늘었다. 이번 완료 로그와 iOS 원시 캡처는 이 보고서에 결과를 보존한 후 제거한다.
재사용 코드·fixture·사용 지침은 보존하고 개발 서버는 유지한다. 승격·npm 게시·Utilverse 채택은 미실행이다.
