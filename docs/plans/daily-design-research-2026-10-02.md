# 2026-10-02 디자인 리서치 반영 기록

입력: `app-portfolio/research/2026-10-02/design-system.md`,
`design-native-selection-pass3.md`, `design-current-project-reconciliation.md`.
리포트는 이미 압축 해제·검증된 상태로 제공됐다. 이 기록은 리포트의 적용 판단이며,
원제품의 실기기 동작이나 HJM 소비 앱의 배포 증거를 새로 만들지 않는다.

| 조사 항목 | HJM 판단 | 이번 반영 |
| --- | --- | --- |
| HJM 1.11.0의 저장·재시도·Undo, 3초 일반 알림과 유지되는 액션 알림 | 현재 계약과 예제가 이미 있다. 이름만 바꾼 중복 컴포넌트를 만들지 않는다 | 기존 구현 유지 |
| Google Photos의 대표 항목과 묶음 전체 | 범위를 보이지 않게 추정하면 예상보다 많은 항목에 작업이 적용될 수 있다. 선택 전에 대상 수를 드러내는 구성이 재사용 가능하다 | Web/Native `실험/구성/상호작용 예제/대표 항목과 묶음 전체 선택`, [품질 기준](../INTERACTION_QUALITY.md) |
| Excalidraw의 작업 표면 안 첫 행동 | HJM `EmptyState`와 온보딩 화면이 이미 있다. 실제 저장 경계는 제품이 결정해야 한다 | 새 일반 컴포넌트 보류, 제품의 첫 작업 흐름에서 판단 |
| Bluesky의 선택적 추천 Retry/Skip와 Expensify의 오프라인 상태 | HJM의 실패·재시도 예제와 제품 상태 소유 원칙이 기본 행동을 설명한다. 오프라인 큐와 권한·지속성은 제품 계약이다 | 기존 예제 재사용, HJM 네트워크 큐 추가 보류 |
| Highcharts의 차트·표 동기화와 Squoosh의 전후 비교 | 하나의 데이터 선택을 여러 표현이 공유하는 원칙은 유효하다. 이번에는 대상 제품·데이터와 네이티브 읽기 순서가 정해지지 않았다 | 제품 과제와 접근성 검증이 정해진 뒤 실험 |
| Todoist의 배치 선택과 Apple/Google Photos의 작업 범위 | 컨텍스트 메뉴·롱프레스는 보조 경로로 두고, 범위·대상 수·적용 단계를 분리한다. 플랫폼별 제스처를 그대로 복제하지 않는다 | 이번 선택 범위 실험에 명시 버튼 경로 반영 |

이번 예제는 로컬 상태만 바꾸며 파일이나 서버에 공유하지 않는다. 기본·어두운 테마·큰 글자와
Web/Native의 조작 경로를 Storybook에 등록했다. 실제 공유·다중 선택·권한·취소는
제품의 의미가 정해질 때 계약화한다. 사용자 승인 전 스토리북 배포로 이동하지 않는다.
