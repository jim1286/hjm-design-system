# 관련 입력 그룹 실험

검토일: 2026-10-07 · 상태: 구현 전 권장 후보 · HJM 기준: 2f3f29d

## 확인한 공백

[Component Gallery](https://component.gallery/components/fieldset/)의 32개 목록에는 일반 fieldset,
단일 필드 프레임, 선택 그룹, 입력 부가 요소가 섞여 있다. 같은 이름으로 모두 대체하지 않는다.
[GOV.UK](https://design-system.service.gov.uk/components/fieldset/)의 주소 예제는 네 입력을 하나의
질문 아래 묶으며 각 필드의 label·autocomplete를 유지한다. 실제 1280×720 화면과 DOM에서
첫 자식 legend, 네 개의 독립 입력, 첫 입력 편집 후 Tab으로 둘째 입력 이동을 확인했다.
스크린리더 낭독을 실행한 것은 아니다.

[Headless UI](https://headlessui.com/react/fieldset)는 native fieldset과 aria-labelledby로 연결한
div 제목을 사용한다. 소스 문서만 대조했으며 실제 예제 화면은 미검토다. GOV.UK의 legend
구조와 같다고 기록하지 않는다. 외부 코드나 스타일은 복사하지 않는다.

| 기존 HJM | 충족 범위 | 일반 그룹으로 전용할 수 없는 이유 |
| --- | --- | --- |
| Form | 제출 세션·진행 중 잠금·폼 오류 | Web 내부 fieldset에 그룹 제목 API가 없고 Native는 제출 버튼을 소유한다. 한 폼 안 여러 묶음을 만들려고 Form을 중첩하면 제출 계약이 달라진다 |
| Field / TextField | 하나의 입력 라벨·도움말·오류 | 복수 입력의 공통 질문을 개별 입력 라벨로 바꾸면 관계가 사라진다 |
| CheckboxGroup / RadioGroup | 동종 선택과 그룹 의미 | 주소·연락처처럼 이종 입력을 담는 API가 아니다 |
| DateEntry / DurationField | 날짜·시간 부분 입력의 그룹 | 값·검증 정책이 해당 도메인에 한정된다 |

## 구현 대상

권장 실험은 `실험/구성/입력과 작성/관련 입력 묶음`이다. 아직 Storybook에 등록하지 않았으며
15개 실험 수에 더하지 않는다. API 이름은 기존 export와 충돌하지 않는지 구현 직전 재검사한다.

- 공통 계약: 그룹 이름·설명·그룹 오류의 의미를 소유한다. 입력 값·주소 형식·국가별 순서·검증 시점·제출은 제품이 소유한다.
- Web: fieldset의 첫 legend로 그룹을 이름 짓는다. 각 입력의 id·label·autocomplete와 개별 오류를 유지한다. Form을 새로 만들거나 제출 버튼을 추가하지 않는다.
- Native: 부모를 단일 accessible 요소로 만들어 자식 입력을 숨기지 않는다. 그룹 문맥과 개별 label을 연결할 공개 경로가 필요하다. 단순 시각 제목을 추가한 것으로 접근성 동등성을 주장하지 않는다.
- 오류: 그룹 오류는 한 번 보이고, 영향을 받는 입력만 invalid가 된다. 개별 오류와 그룹 설명을 덮어쓰지 않는다. DateEntry의 최근 반복 오류 수정과 의미를 맞추되 날짜 검증 엔진은 가져오지 않는다.
- 비활성: Web fieldset의 잠금과 Native 자식 잠금이 실제로 동일한지 확인한다. 자식 props를 무분별하게 clone하거나 wrapper만 비활성화한 상태를 완료로 세지 않는다.
- 배치: 공통 세로 리듬과 줄바꿈을 제공한다. 화면 스크롤·키보드 회피는 화면 host에 남기며 중첩 스크롤을 만들지 않는다.

## 실험·승격 확인 항목

한 폼 안 배송지/연락처 두 묶음을 두고 개별 이름 충돌, 그룹 설명 연결, 일부 오류와 그룹 오류의
공존, 실패 후 입력 보존, 잠금 중 편집 차단, 재활성화, 동적 필드 추가/제거를 검증한다.
공개 API를 사용하는 양쪽 Storybook과 사용 지침이 필요하다. 320px/큰 글자·RTL·light/dark·
서로 다른 제품 팔레트, 키보드 순서, VoiceOver/TalkBack에서 개별 입력 접근을 검증한 뒤 승격한다.

나머지 31개 원본의 UI 검토는 미완료다. 일반 그룹 실험의 필요성을 확인한 것과 해당 카테고리
전수 검토 완료를 구분한다. 사용 지침의 Form 선택 기준에 확인한 경계를 먼저 반영했다.
