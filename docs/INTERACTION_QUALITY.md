# 제품 상호작용 적용과 품질 기준

검토일: 2026-10-02 · 적용: HJM Web/React Native 및 이를 채택하는 제품

## 목표와 소유권

사용자가 참고한 인터랙션의 반응성과 완성도가 HJM으로 만든 제품에도 이어지기를 요청했다.
모양만 조합하거나 성공 장면만 확인하면 입력 지연·중단·실패 복구가 제품마다 달라지므로,
입력 → 반응 → 확정 → 복구를 하나의 구현 단위로 다룬다. 이 문서는 그 적용 기준이다.
레퍼런스와 동일한 성능을 이미 달성했다는 보증이나 특정 라이브러리 교체 지시가 아니다.

- HJM: 토큰, UI 상태, 포커스·접근성, 지원 플랫폼의 모션·제스처 표현, 컴포넌트 취소·정리.
- 제품: 도메인 상태, 서버 확정·권한, 재시도 멱등성, 초안 저장, Undo 역연산, 라우팅·캐시.
- 구현자는 설치된 HJM 버전의 export·호환 문서를 확인한다. 저장소의 신규 API가 설치된
  게시 버전에 있다는 가정으로 import하지 않는다. 이미 Query mutation 등이 상태를
  소유하면 별도 action-session을 겹쳐 만들지 않고 같은 행동 규칙을 연결한다.

## 구현된 예제와 선택 기준

아래는 현재 소스·Storybook에서 확인할 수 있는 항목이다. 레퍼런스 60개 전체 구현 목록은 아니다.
API 안정성, 스토리북 배포 분류, npm 게시와 실제 제품 적용 상태는 각각 구분한다.

| 필요 동작 | 재사용할 구현 | Storybook 위치 및 채택 상태 |
| --- | --- | --- |
| 탭 선택과 별도 작업 실행 | BottomNavigation + Button/IconButton, 기능별 4개 묶음 안의 10개 표현 | 배포/컴포넌트/탐색/내비게이션 바; 전체 비교는 배포/구성/내비게이션 바 비교 |
| 저장 중 중복 차단·실패 후 재시도 | 기존 Button + 선택적 createActionSession 또는 제품 mutation | 실험/구성/공통 동작/저장과 재시도 |
| 저위험 값 즉시 반영·실패 복구 | action-session optimisticValue, 제출 단위 응답 검증 | 실험/구성/공통 동작/즉시 반영과 복구 |
| 보관 후 실행 취소 | 기존 버튼·상태 UI + 제품 역연산 | 실험/구성/공통 동작/보관과 실행 취소 |
| 선택 후 적용·취소 | Sheet + Button, 임시 선택과 확정 값 분리 | 실험/구성/상호작용 예제/선택 후 적용·취소 |
| 닫은 뒤 초안 이어쓰기 | Sheet + TextField, 시트 밖의 초안 상태 | 실험/구성/상호작용 예제/닫았다 열고 초안 이어쓰기 |
| 역순 응답에도 최신 검색 유지 | TextField + 읽기 요청의 세대 구분 | 실험/구성/상호작용 예제/늦은 응답보다 최신 검색 유지 |
| 순서 이동·행 작업·내용 전환 | sortable, swipe-actions, content-transition 등 선택적 adapter | 실험/구성/드래그·스와이프·모션; API별 지원 범위는 아래 문서 |
| 대표 항목과 묶음 전체를 구별해 적용 | 기존 Button의 선택 상태와 명시적 적용 동작 | 실험/구성/상호작용 예제/대표 항목과 묶음 전체 선택. 화면 안 시뮬레이션이며 실제 공유는 하지 않음 |
| 네이티브 이미지·시트·키보드 조작 | ImageViewer, GestureSheet, KeyboardDock 등의 선택적 adapter | 실험/구성/이미지·시트·키보드 조작; 호환 개발 클라이언트 필요 |

실험 예제는 검토용이며 사용자의 승인 후 스토리북 배포로 이동한다. 이번 지침 갱신으로
실험을 자동 승인하지 않는다. 초안 데모는 화면 내 상태만 보존하며 프로세스 종료 복구가 아니다.
검색·실패 데모의 인위 지연은 설명용이다. 제품에 최소 대기 시간을 복사하지 않는다.

2026-10-02 조사에서 그룹의 대표 항목과 전체 구성원을 같은 선택으로 오인할 위험을 확인했다.
[Google Photos의 사진 묶음 안내](https://support.google.com/photos/answer/14169846?hl=en-uk)는
표지와 묶음 전체의 작업 범위를 구분한다. 여기서 가져온 원칙은 **대상 수와 범위를 적용 전에
문구로 보여주는 것**이며 제품별 기본 선택이나 공유 정책까지 복제하지 않는다. 길게 누르기나
작은 배지만으로 범위를 숨기는 대안은 발견성과 접근성 때문에 채택하지 않았다. 선택 범위는
제품의 안정적인 항목 ID와 권한을 기준으로 확정하고, 실제 전송·취소·복구는 제품이 소유한다.
Web/Native 스토리는 이 의미를 확인하는 실험 UI이며 외부 서비스의 동작·자산 복제가 아니다.

구체 API·제약: [실행과 복구](../packages/design-contracts/docs/action-session.md),
[선택적 상호작용](interaction-adapters.md), [Expo 연결](expo-interactions.md),
[전체 스토리 분류](STORYBOOK_NAVIGATION.md).

## 제품에서 구현하는 순서

1. 제품 DESIGN 문서에 사용자 과제, 참조한 동작과 선택 이유, 기존 HJM 항목, 적용 표면을 적는다.
   참고 영상은 시각·동작의 목표다. 원본을 같은 기기에서 직접 측정하지 못했다면
   원제품 FPS·응답 시간을 추정하거나 동등한 성능이라고 쓰지 않는다.
2. 입력·처리 중·확정·오류·취소·재시도·뒤로가기의 상태와 소유자를 먼저 정한다.
   누름 반응은 즉시 표시하고 성공은 실제 확정 이후에 표시한다.
3. 기존 토큰·컴포넌트로 구성한다. 시간·easing·spring은 공개 토큰을 사용하고 임의의
   숫자를 앱마다 추가하지 않는다. 새로운 표현이 필요하면 HJM 실험에 지원 표면을 함께 등록한다.
4. 제품 API와 연결한다. 중복 요청, 이전 응답, 화면 이탈, 계정 변경, 초안 보존과 복구를 검증한다.
   action-session의 operationId는 서버 멱등 키가 아니며 reset은 서버 취소가 아니다.
5. 제품 데이터·실제 화면에서 아래 품질을 확인한다. 검증 기록을 제품 문서/PR에 연결한다.
   Storybook 성공을 제품 통합·기기 성능의 증거로 대신하지 않는다.

리퀴드 토스트는 Native 선택적 표현이다. 기본 시작점은 32×32 원형, 펼쳐진 카드 반경은 12이며
웹에서는 기존 일반 토스트로 표시한다. [현재 계약](../packages/react-native/docs/liquid-toast.md)을 따른다.

## 자연스러운 표현의 기본 조건

- 모션은 현재 위치·선택·상태 변화의 의미를 보여준다. 강조는 사용자의 행동에 연결한다.
- 손가락 추종은 중간에 끊거나 반대로 조작할 수 있어야 한다. 취소·빠른 재입력 시 튀거나
  원점으로 순간 이동하지 않는지 확인한다. 모션 종료까지 다음 입력을 일괄 막지 않는다.
- 로딩 중 공간을 예약해 터치 대상이 이동하지 않게 한다. 로그인은 기존 카드 크기를 유지하고
  버튼들을 중앙 로딩 하나로 바꾸며 로딩 아래 문구를 추가하지 않는다.
- 열기·닫기 뒤 포커스, 목록 위치, 초안을 복원한다. 드래그·스와이프는 같은 결과의 버튼 경로를 둔다.
- 큰 글자·작은 화면·키보드·safe area에서도 핵심 액션이 보인다. reduced motion에서도 결과는
  유지하고 공간 이동·반복 장식을 줄인다. 소리·햅틱은 결과를 전달하는 유일한 수단이 아니다.

## 성능 목표와 측정

아래는 앞으로 달성할 제품 품질 목표이며 기존 제품의 측정 결과가 아니다. 네트워크 완료 시간과
첫 시각 반응, 모션 재생 길이를 서로 다른 지표로 기록한다.

| 항목 | 목표·판정 | 확인 방법 |
| --- | --- | --- |
| 누름 반응 | 로컬 시각 반응 p95 100ms 이내를 초기 제품 목표로 설정 | 동일 기기·빌드·데이터의 반복 입력 영상 또는 이벤트/프레임 기록; 표본 수와 측정 구간 기재 |
| 웹 응답성 | 실사용 INP p75 200ms 이하를 목표로 관리 | 모바일·데스크톱을 나눠 field data 확인; 로컬 자동화 결과를 field INP라고 보고하지 않음 |
| 앱 연속 모션 | 대상 기기의 실제 주사율에서 안정적 프레임 유지 | Release 실기기에서 UI/JS 프레임 지연·누락 프레임·긴 작업 측정. 60Hz 간격은 약 16.7ms, 120Hz는 약 8.3ms; 120fps를 일괄 보장하지 않음 |
| 비용과 지속성 | 기존 화면 대비 설명되지 않는 메모리·프레임 회귀가 없어야 함 | 동일 시나리오 반복 후 메모리·해제 여부, 긴 목록·이미지·겹치는 효과 비용 비교 |
| 의미와 복구 | 중복 실행·오래된 응답 덮어쓰기·초안 손실·닫힌 UI 잔류가 없어야 함 | 연속 입력·실패·역순 응답·중간 취소·빠른 뒤로가기를 실제 제품 경로에서 확인 |

100ms는 이번 요청에 따라 채택한 내부 시작 목표이며 외부 제품의 실측 수치가 아니다.
웹 INP 기준은 [web.dev](https://web.dev/articles/inp), 앱의 프레임·Release 측정 원칙은
[React Native](https://reactnative.dev/docs/performance)를 참고한다.
[Reanimated 성능 가이드](https://docs.swmansion.com/react-native-reanimated/docs/guides/performance/)의
최적화는 설치된 RN/SDK 버전과 맞는지 확인한 뒤 적용하며 플래그를 무조건 복사하지 않는다.

매 프레임 React state 갱신·전체 트리 재렌더·반복 layout 측정을 피하고, 지원되는 속성은
transform/opacity 및 기존 native driver/worklet 경로를 우선한다. blur·filter·입자·이미지 레이어는
변화하는 영역에 제한한다. 숨겨진 화면·백그라운드·unmount에서 반복 효과와 구독을 정리한다.
측정 없이 모든 UI에 3D/Skia나 새로운 모션 엔진을 붙이지 않는다.

일상 UI 확인은 기존 Expo 개발 서버·클라이언트에서 한다. 성능 판정은 제품 릴리스 검증 때
Release 실기기에서 수행한다. 문서 보완이나 단순 Storybook 확인만으로 native 빌드를 시작하지 않는다.
기존 iPhone 12 문제는 작은 화면과 실제 기기 성능의 회귀 시나리오에 포함한다. 기기가 없으면
동급 기기 또는 미검증 범위와 확인 계획을 명시하며 viewport 에뮬레이션으로 기기 성능을 대체하지 않는다.

## 완료 기록

제품 DESIGN 또는 PR에 다음을 남긴다. 기존 기록 양식이 있으면 같은 필드를 재사용한다.

- 사용자 과제 / 레퍼런스에서 가져온 원리 / 적용한 HJM 버전·항목 / Storybook 상태
- 입력 → 반응 → 확정 → 복구 / 상태 소유자 / 서버·초안·취소의 범위
- 웹·iOS·Android 적용 여부 / 기기·OS·주사율·빌드 / 데이터량·네트워크 조건
- 변경 전후 측정 방법·표본 수·p95 반응·프레임/메모리 결과와 영상 또는 trace 위치
- 키보드·큰 글자·reduced motion·스크린리더 / 실패·중단·역순 응답 확인
- 통과·미검증·회귀 항목 / 미달 시 원인·수정 또는 단순화 / 담당과 재확인 조건

성능에 영향을 주는 새 제스처·화면 전환·대량 목록·효과 변경에서 측정을 갱신한다.
문구 수정마다 전체 장치 시험을 반복하지 않는다. 제품 성능이 미측정이면 ‘동작 확인’까지만
보고하고 ‘레퍼런스 수준 성능 검증 완료’라고 쓰지 않는다.
