# 배포·실험의 계층과 제품 채택 검수

검토일: 2026-10-06

검증 실행·수치·미확인 범위는 [QA 리포트](../qa/2026-10-06-usage-guides.md)에 있다. 원시 캡처·로그·JSON은 QA 리포트 지침(포트폴리오 `docs/QA_REPORT_STANDARD.md`)에 따라 저장소에 두지 않는다.

## 목적과 범위

공통 기능처럼 UI도 공개 라이브러리에서 선택하고, 제품별 테마를 유지한다는 사용자 요청을 검수 기준으로 삼았다. 화면 → 구성 → 컴포넌트 → 토큰 순서로 선택한다. 배포와 실험 모두 같은 계약을 따르되 실험의 승급과 패키지 게시·소비 앱 이관은 별개다.

[제품 채택 지침](../../packages/design-contracts/docs/product-composition-adoption.md)에서 목적별 공개 API, 제품이 공급하는 데이터·문구·팔레트, 검증 범위를 설명한다.

## 전수 목록과 판단 한계

[정적 의존 목록](showcase-hierarchy-2026-10-06.json)은 Web·Native의 배포·실험 제목 328개를 로컬 의존 파일까지 추적한다. 모두 HJM 공개 진입점을 사용한다. 제목 수는 스토리 변형 수가 아니며, import가 있다는 사실만으로 올바른 조합·시각 품질·중복 부재를 증명하지 않는다.

사용 지침은 216개(토큰 12, 컴포넌트 135, 구성 43, 화면 26)이며 색인·필수 형식 검사를 통과했다. 모든 코드 예제를 각각 새 소비 프로젝트에서 재구현한 검증은 아니다.

## 확인 후 수정한 재사용과 배치

- 저장 목록/상세를 ListDetailScreen으로 연결해 목록과 검색 상태를 유지한다.
- 검색·댓글·메시지 입력 예제는 기존 SearchField·MessageComposer를 소비한다. 별도 공개 별칭이나 입력 엔진을 추가하지 않았다. 전송 예제의 상태 처리도 기존 useDemoAction 계약을 사용한다.
- FamilyDrawer 및 참조 흐름의 확정 액션을 Sheet footer로 옮겼다. 선택 옵션은 본문에 유지한다.
- 알림 설정은 고정 상단, 스크롤 본문, 하단 CTA로 나눴다. 관련 Native 예제의 바깥 간격은 Container에 맡겼다.
- 내비게이션 예제의 일괄 둥근 모서리 덮어쓰기를 제거했다. 플랫폼별 표현 자체는 별도 구현으로 유지한다.
- OTP 재전송마다 입력 포커스가 복원되도록 횟수 상태를 사용했다.
- 보라·초록 팔레트 예제에서 같은 공개 입력 구성을 재사용한다. 샘플 팔레트는 특정 소비 앱 적용 증거가 아니다.

## 남아 있는 검증과 구분

사용자가 검증 범위를 컴포넌트·구성·화면 각 3개로 좁혀, 독립 재구현은 아래 9종으로 완료했다. 전체 216개 코드 예제 독립 컴파일은 이번 범위에서 제외했으며 미완료 의무 작업으로 남기지 않는다. 216개 형식·색인 검사는 유지하고, 9종 결과를 전체 지침의 독립 검증으로 확대 해석하지 않는다. 스토리의 개별 함정 기록도 모두 해결된 것은 아니다. 수정한 검색·갤러리·대시보드·모션 예제의 과거 불일치 기록은 현재 계약에 맞게 갱신했다. 컨테이너를 부모가 제공하는 구성, 실제 서버가 없는 로컬 예제, 플랫폼 입력 어댑터는 자동으로 중복이나 규칙 위반으로 판정하지 않는다.

번들 크기 경고와 TypeScript 생성 dist의 공백 경고는 남아 있다. 검사 통과와 경고 없음은 다르다. 실험 승급·npm 게시·각 소비 앱의 실제 적용과 릴리스는 수행하지 않았다.


## 2차 독립 재구현 — 단계별 3개, 총 9개

사용자의 최종 요청(2026-10-06)에 따라 컴포넌트·구성·화면 각 3종을 검증했다. 기존 구현·Storybook·화면을 보여주지 않은 독립 에이전트 세 명이 사용 지침과 공개 타입 선언만 읽고 소비 예제를 만들었으며, 부모 에이전트가 실제 구현과 비교·실행했다. 라이브러리 엔진을 새로 구현한 시험이 아니라 지침으로 공개 API를 선택하고 조립할 수 있는지 확인한 시험이다.

| 단계 | 대상 |
| --- | --- |
| 컴포넌트 | Button, Dialog, MessageComposer |
| 구성 | TimeSelection, InputSheet, DataLayouts |
| 화면 | Saved, Profile, Search |

Web·Native 총 18개 TSX가 strict, exactOptionalPropertyTypes, noUncheckedIndexedAccess, skipLibCheck=false 조건을 통과했다. API를 `any`나 가짜 선언으로 대신하지 않았다. Native DOM 전역 충돌은 테스트 호스트 설정에서 제거했다.

### 발견과 수정

- Native Button의 고정 높이가 큰 글자 줄바꿈을 잘랐다. 문자열·숫자 라벨은 최소 높이를 유지하면서 내용에 맞게 늘어나고, 행 안에서 줄바꿈하도록 수정했다. 기본·2배 글자 및 로딩 시 높이 유지 회귀 검사를 추가하고 화면을 다시 확인했다. 사용자 정의 이미지 자식은 기존 높이 계약과 growWithContent 선택을 유지한다.
- Button 지침에 로딩 시 라벨·아이콘 숨김, 중앙 스피너 하나, 기존 children과 접근성 이름·포커스·크기 유지 규칙을 명시했다. 독립 에이전트가 최초 누락과 개정 후 해결을 각각 기록했다.
- Dialog 지침의 “Promise를 기다리지 않고 닫음” 설명을 실제 계약인 “성공 후 닫힘, 실패 시 초안과 창 유지”로 정정했다. onActionError, Web/Native 폭 차이, Native 스크롤 본문 소유도 정리했다. Native 기본 스토리는 액션 콜백에서 직접 닫지 않고 공통 계약에 맡긴다.
- 메시지 작성 지침에 섞인 SearchField busy 설명을 MessageComposer의 양 플랫폼 pending 계약으로 수정했다.
- 앞선 여섯 표본에서 확인한 시간 선택 Notice 위치, 버튼 순서, 빈 입력 완료 비활성화, 검색 중 잠금 범위, QR fallback 간격, Masonry 높이 소유, 검색 카테고리 설명도 맞췄다. 초안 취소처럼 제품 소유 정책을 단일 정답으로 강제하지 않았다.

### 실행 결과와 한계

- Web: 9종 × 320/1200px × 기본/다크/2배 글자 = **54조건**. 최종 렌더 오류·axe 위반·가로 넘침 0. Button 작은 타깃의 hitSlop이 호스트 밖으로 나간 초기 결과는 공통 Container gutter를 제공한 뒤 재검증했다. 숨김 overflow로 결과를 감추지 않았다.
- Web 조작 **9개 흐름 통과**: 저장 해제/Undo/컬렉션, 프로필 실패/취소 확인/재저장, 검색 지우기/포커스, 시간 선택 및 입력 시트 반복 실패/성공, 데이터 표시 전환, Button 로딩 중 중복 차단/disabled/크기·포커스 유지, Dialog 실패 두 번 뒤 성공/초안/포커스 복귀, Composer 공백 차단/줄바꿈/실패 보존/재시도 성공 후 비우기.

## 인수인계의 토큰 미연결 후속 수정

2026-10-06 9종 독립 검증 이후, 기존 인수인계에 남아 있던 Web 겹침 순서·그림자 문제를 현재 소스에서 재확인했다. Web CSS의 500–1400 숫자와 popup JS의 별도 숫자는 foundation `layer`를 읽지 않았고 `--hjm-shadow-*`도 표면에서 소비하지 않았다.

- Web provider가 `--hjm-layer-*`를 내보내고, 고정 바·popup·modal·tooltip·toast는 각 의미 토큰을 소비한다. 모달 내부 popup은 소유 모달 + 1, 초점 받은 건너뛰기 링크는 toast + 1 관계를 유지한다. 컨트롤 내부 장식의 0/1/2는 전역 층으로 바꾸지 않는다.
- 일반 떠 있는 표면은 `shadow.floating`, 큰 강조 표면은 `shadow.overlay`를 사용한다. 포커스 링·선택 테두리·스위치 손잡이는 높이 그림자와 구분해 기존 상태 계약을 유지했다. Native Surface도 별도 blur 6 대신 공통 floating 그림자를 쓴다.
- 관련 토큰·컴포넌트·구성 지침의 이전 숫자를 함께 갱신했다. Menu와 같은 portal 배치로 이미 바뀐 Menubar의 오래된 absolute 배치 설명도 정정했다.
