## 범위와 판정

- 기준 저장소: `hjm-design-system`, 착수 main `767d47f7`. 다른 세션의 dirty 및 생성물을 보존했다.
- 지침 본문 **60/60** 확인. Web·Native 양쪽 **51**, Web 전용 **6**, Native 전용 **3**. 대응 Storybook 등록 **111개**와 등록에서 직접 연결한 로컬 소스·fixture **167파일**의 경로/import를 대조했다.
- 167파일의 `@hjmds/*` import subpath를 현재 각 `package.json.exports`와 대조한 결과 누락 0. 이는 이름 있는 export의 의미·패키지 게시·제품 실제 채택 증거가 아니다.
- 모든 행의 **D**는 지침 본문·등록·직접 연결 소스 경로·공개 import 경로 확인이다. **B**는 추가로 상태 처리 구현 본문을 읽어 입력·pending·실패·복구 분기까지 대조한 범위다. D만인 행을 동작 검증 완료로 세지 않는다.
- 수정 범위는 구성 지침과 showcase 조합이다. 공개 이름만 다른 wrapper나 별도 저장 엔진을 추가하지 않고 기존 `createActionSession`, `Sheet`, `Steps`, `Dialog`, `SegmentedControl`, `BottomNavigation` 계약으로 보강했다.
- 실기기·브라우저 상호작용·스크린리더·키보드 실측은 이번 하위 감사에서 **미실행**. OS 최대 글자 크기와 그 모사 조건은 범위 제외. 기존 관련 스토리는 실행하지 않았다.

## 확정 발견과 수정

### C-01 — 구성 이름이 약속하는 흐름과 코드 골격 불일치 (P1, 수정)

- 위치: `packages/design-contracts/docs/usage/compositions/reference-first.md:47`, `reference-review.md:47`, `reference-settings.md:47`.
- 트리거: 첫 작업·검토·설정 이탈 지침을 그대로 따라 구현할 때. 이전 첫 작업은 정적인 Steps, 검토/설정은 같은 닉네임 Form만 제시했다.
- 영향: 초안과 확정값 분리, 단계 복귀, 확인 후 버리기 같은 핵심 흐름이 소비자의 재구현으로 밀렸다. 실제 showcase의 `Editor`에는 이미 해당 분기가 있었다.
- 최소 개선: 독립 공개 컴포넌트가 아닌 조합임을 명시하고 Web/Native 실제 Editor 링크, 공통 session 골격, 흐름별 단계·dirty·discard·서버 확정·영속 초안 경계를 작성했다. Form이 흐름 전체를 제공하는 것처럼 읽히던 표도 고쳤다.
- 확인: 문서/소스 정적 대조. 골격에는 제품 `saveToServer`, validation, i18n, router 연결이 필요하며 완성 제품 코드라고 주장하지 않는다.

### C-02 — 입력 시트의 저장이 즉시 닫기뿐임 (P1, 수정)

- 위치: `showcase/web/src/patterns/InputSheet.stories.tsx:15`, `showcase/native/src/InputSheet.stories.tsx:17`.
- 트리거: 빈 입력, 실패 응답, 저장 연타 또는 저장 중 닫기.
- 영향: 이전 예제는 저장 없이 닫혔고 문서가 요구한 pending/실패/입력 보존을 실행해 볼 수 없었다.
- 최소 개선: 빈 값 차단, 제출값 캡처, 기존 session으로 동기 중복 실행 방어, Sheet.busy·입력 잠금, 실패 Notice, 같은 주 버튼 재시도, 성공에만 닫기, 메모리 초안 유지와 확정된 이름 표시. 양쪽에 데모 실패 유도 버튼을 추가했다.
- 확인: 실제 서버가 없는 350ms 데모 요청이며 서버 idempotency·영속 초안은 제품 책임이다. 관련 session 9건 통과, UI의 실기기 닫기/포커스는 미실행.

### C-03 — 단계별 드로어에 저장 실패·중단 복귀가 없음 (P1, 수정)

- 위치: `showcase/web/src/patterns/FamilyDrawer.stories.tsx:18`, `showcase/native/src/FamilyDrawer.stories.tsx:18`.
- 트리거: 마지막 단계 저장 실패 또는 중간에 닫고 다시 열기.
- 영향: 이전에는 마지막 버튼이 바로 성공 처리했고 다시 열 때마다 0으로 초기화했다. Native footer를 가로 Stack으로 덮어 지침의 세로 행동 배치와도 달랐다.
- 최소 개선: 비동기 session, pending 동안 이동/닫기 차단, 실패한 현재 단계에 `currentStepStatus="error"`와 Notice, 동일 위치 재시도, 중단한 단계로 이어하기, 성공 후 새 시작 때만 초기화. footer 직접 자식 순서를 Web 보조→주, Native 주→보조로 정리했다.
- 확인: 정보 단계 데모이며 제품별 실제 초대·설정 입력 데이터는 포함하지 않는다. 실기기와 저장 API 연결은 별도다.

### C-04 — 이미 해결된 Native Dialog 비동기 닫기 우회 지침 (P1, 수정)

- 위치: `packages/design-contracts/docs/usage/compositions/floating-action-button.md:73`, `:165`; 실제 계약 `packages/react-native/src/overlays.tsx:466`.
- 트리거: 저장 Promise를 primaryAction에서 실행할 때.
- 영향: 문서는 콜백 직후 무조건 닫힌다고 설명하고 ref로 닫기를 무시하게 했지만 현재 Dialog는 Promise를 기다리고 실패 시 열린 상태를 유지한다. 불필요한 이중 pending/닫기 정책이 생겼다.
- 최소 개선: Promise 반환 유지, 내장 중복 실행·loading·busy dismiss 정책, 거절은 `onActionError`로 제품 문구에 연결하도록 고쳤다. `void save()`로 Promise를 버리는 실제 함정을 명시했다.
- 확인: 소스 확정. Web TextArea에 onValueChange가 없다는 별도 설명은 현재 타입과 일치하므로 유지했다.

양 플랫폼 `SelectionScope.stories.tsx`의 CSF `meta.component`를 직접 소비했다. Web fixture는 Showcase Bundler 설정 아래 `showcase/web/src/patterns/selection-scope.browser.test.tsx`, Native는 `packages/react-native/test/selection-scope-showcase.test.tsx`에 두었으며 private 함수 추출·공개 API 추가·Native import 확장자 변경은 하지 않았다.

- 처리 중에는 “범위를 고른 뒤 적용하세요” 대신 “N개 공유 대상을 확인하고 있어요”를 표시한다. 이 예제의 초안은 선택 범위이며 텍스트 입력은 없다.
- **GREEN:** Showcase Web `pnpm exec vitest run --config vitest.browser.config.ts src/patterns/selection-scope.browser.test.tsx`를 Chromium/WebKit/Firefox 순차 실행해 각각 **2건 통과**. Native `pnpm exec vitest run test/selection-scope-showcase.test.tsx` **2건 통과**. 기본 1개/전체 3개, 키보드 선택, 중복 적용, pending 변경 거부, 실패 뒤 같은 선택 재적용, 성공 뒤 새 선택으로 결과 초기화, 적용 버튼 초점 유지와 이미 이동한 외부 초점 보존을 확인했다.

### LiveList 실제 preview 후속

양 `live-list-preview.tsx`와 `showcase/shared/live-list.ts`를 직접 소비했다. 실제 기능은 단건/3개 추가·첫 행 삭제·역순·id별 메모 편집·모션 정지다. filter/항목 선택/서버 동기화는 제공하지 않아 검사 범위로 꾸미지 않았다.

- **RED/수정:** WebKit에서 초점 있는 첫 입력을 pointer로 삭제하면 `activeElement=body`로 사라졌다. 삭제 클릭에서 먼저 안정적인 삭제 버튼으로 focus하고 마지막 행이면 추가 버튼으로 이동한다. Native preview와 Storybook canvas에 ScrollView가 없음을 host에서 확인해 KeyboardAvoiding→ScrollView(`keyboardShouldPersistTaps="handled"`)를 연결했다. Native 변경 결과 iOS announcement 0회도 재현해 기존 PatternStatus를 사용했다.
- shared 모델의 변경 메시지에 추가 후 총 개수·삭제한 기록·역순 후 첫 기록을 포함해 같은 행동의 연속 결과도 구분한다. 빈 목록 삭제·1행 이하 역순은 실제 변화가 없는 상태를 그대로 반환한다. 항목 key/ID·메모 저장 방식은 유지했다.
- **GREEN:** `showcase/web`에서 `pnpm exec vitest run --config vitest.browser.config.ts src/patterns/live-list.browser.test.tsx` **Chromium/WebKit/Firefox 각각 3건**; `packages/react-native`에서 `pnpm exec vitest run test/live-list-showcase.test.tsx` **3건**; `showcase/web`의 `pnpm exec vitest run src/patterns/live-list.test.ts` **2건** 통과. 연속 추가·역순·모션 토글의 노드/초안/초점 유지, id 유일성, 삭제 후 late edit 비복원, 빈 상태 재추가, Web 긴 문서 스크롤 후 마지막 입력, Native 스크롤 연결 및 연속 iOS announce 호출을 확인했다.
- Web 최초 스크롤 assertion은 Playwright fill의 부분 가시성 자동 스크롤을 전체 입력 노출로 가정한 fixture 오류였다. 실제 scrollIntoView 후 위치를 확인하도록 수정했다. Native는 host 연결·함수 호출 증거이며 실제 OS 스크롤/키보드/VoiceOver·TalkBack을 증명하지 않는다. 기본 글자·reducedMotion에서 데이터 흐름을 실행했으며 전체 모션 엔진 품질 검사는 아니다. 본 작업 PNG 2개만 정리했고 scoped diff check 통과. 모델 변경을 포함한 양 타입 검사는 부모 통합 범위다.
